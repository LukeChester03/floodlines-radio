# Agent fleet

The agent-remote fleet (dispatcher, planners, workers, reviewers) works in this
repo. It reads the lines below from the default branch; change them with a PR.

- short: floodlines
- aliases: radio, floodlines-radio
- test: `npm run build`
- setup: `npm ci`

There is no test suite and no linter yet. The only check that exists today is the
build (`npm run build`), so it is the test command.

## Protected areas

Agents MUST respect these; they are security-critical.

- NEVER send email. No agent touches the Gmail connector. Pitches go out only via the main Claude session after the user confirms recipients.
- `firestore.rules`, `firebase.json`, `.firebaserc`, `src/firebase-config.json`: changes need the user's approval. Rules must keep access limited to the shared band login floodlinesbanduk@gmail.com. Never deploy rules or anything to Firebase from an agent, and never write to the production Firestore (no scripted writes, no tests against prod).
- `src/data/stations.json` is generated by `npm run merge`; edit `research/` or `scripts/overrides.json` instead. Station facts (especially email addresses) must come from the station's own website, never guessed.
- `src/data/sent-log.json` is append-only, written only after real sends.
- Deploying: build, then commit `dist` onto `gh-pages` as a normal push. Force-pushing `gh-pages` is denied; do not attempt it. Only deploy when the user asks.
